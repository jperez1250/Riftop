## 2025-05-18 - RateWindow Timestamp Saturating Subtraction and Zero Max Age Flaws
**Issue:** `RateWindow::add` used `now.saturating_duration_since(*last_ts)` to check if a new packet sample arrived within 100ms of `last_ts`. When `now < *last_ts` (e.g. out-of-order packets or clock skew/regression), `saturating_duration_since` returns `Duration::ZERO`, which evaluated to `< 100ms`, incorrectly merging old out-of-order packet bytes into the latest sample bucket. Additionally, `RateWindow::rate` did not guard against `max_age` being `Duration::ZERO`, leading to division by zero (`f64::INFINITY`).
**Fix:** Updated `RateWindow::add` to compute absolute duration difference (`if now >= *last_ts { now.duration_since(*last_ts) } else { last_ts.duration_since(now) }`) before comparing against the 100ms bucket threshold. Updated `RateWindow::rate` to return `0.0` early if `max_age.is_zero()`.
**Prevention:** Unit tests covering `RateWindow` edge cases with `Duration::ZERO` and out-of-order sample timestamps ensure zero-division safety and correct sample bucket separation.

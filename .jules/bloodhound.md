## 2025-02-18 - Out-of-Order Packet Timestamp Panic and Rate Window Bucket Merging
**Issue:** `FlowTable::expire` and `AlertEngine::evaluate` used `Instant::duration_since`, which panics at runtime if `now` is earlier than the recorded flow timestamp or previous check timestamp (such as when packets arrive out-of-order or during offline PCAP replay). Additionally, `RateWindow::add` relied on `now.saturating_duration_since(*last_ts)`, which evaluated to `0` when `now < *last_ts`, causing packets older than 100ms to incorrectly merge into future sample buckets.
**Fix:** Replaced `duration_since` with `saturating_duration_since` in expiration and alert evaluation to prevent runtime panics when time regresses. Updated `RateWindow::add` to compute bidirectional timestamp differences (`if now >= *last_ts { now - *last_ts } else { *last_ts - now }`) before merging samples within 100ms.
**Prevention:** Always use `saturating_duration_since` or explicit timestamp guards for `std::time::Instant` calculations involving network packet timestamps or snapshot times that may regress.
